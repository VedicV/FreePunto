# Посібник: Тестування FreePunto та робота з дозволами macOS (TCC)

## Чому виникає проблема з дозволами (Accessibility)?

У macOS системні дозволи на керування вводом та перехоплення клавіш (`Accessibility`, `ListenEvent`, `PostEvent`) регулюються підсистемою **TCC (Transparency, Consent, and Control)**.

### Механізм прив'язки дозволів:
1. За відсутності платного сертифіката Apple Developer локальна збірка підписується **ad-hoc** підписом (`codesign --force --sign -`).
2. Для ad-hoc підпису macOS генерує вимогу підпису (Designated Requirement), яка прив'язується до **хешу бінарного файлу (`CDHash`)**:
   ```
   # designated => cdhash H"e4ac24dd7c450466a2308bea1de37783bccbdee7"
   ```
3. Будь-яка зміна у коді Swift або метаданих (`Info.plist`) після перекомпіляції створює **новий `CDHash`**.
4. З точки зору безпеки macOS, новий `CDHash` — це новий виконуваний файл. Старий запис у базі TCC перестає відповідати новому бінарнику, і `AXIsProcessTrusted()` повертає `false`.

## Головні підводні камені, виявлені під час розробки

1. **Динамічний `BUILD_NUMBER` у скриптах**:
   Якщо у `build_app.sh` стоїть `$(date +%Y%m%d%H%M)`, кожен запуск скрипта змінює `Info.plist`, навіть якщо жоден рядок коду не змінився. Це генерувало новий підпис при кожній спробі тестування.

2. **`tccutil reset` у скриптах оновлення**:
   Виклик `tccutil reset Accessibility ...` повністю видаляє застосунок із бази TCC, змушуючи користувача щоразу вручну заходити в Системні параметри, вводити пароль і додавати застосунок заново кнопкою `+`.

3. **Конфлікт шляхів (`dist/` проти `/Applications/`)**:
   Запис TCC прив'язується до шляху та бандла. Якщо користувач дав дозвіл для `/Applications/FreePunto.app`, а розробник запустив `dist/FreePunto.app`, macOS вважає його ненадійним (`not trusted`).

4. **Запуск напряму з термінала (`.../Contents/MacOS/FreePunto &`)**:
   При запуску бінарника напряму з термінала macOS прив'язує запит на глобальне перехоплення клавіш до **процесу термінала** (Terminal.app, iTerm або IDE), а не до FreePunto. Застосунок не з'являється у списку Accessibility.

5. **Перевірка дозволу з `prompt: false`**:
   Якщо застосунок перевіряє доступ через `AXIsProcessTrustedWithOptions([kAXTrustedCheckOptionPrompt: false])`, macOS **не показує системний діалог** і **не додає** застосунок у список налаштувань Доступності у вимкненому стані.

6. **Втрата змінних середовища при `open`**:
   Команда `open /Applications/FreePunto.app` запускає застосунок через `LaunchServices`, але не передає змінні оболонки (наприклад, `FREEPUNTO_LOG_FILE=/tmp/...`). Логування не активувалося при звичайному запуску.

## Як правильно тестувати (Золоті правила)

### Правило 1. Тестувати бізнес-логіку автономно через CLI
95% функціоналу (розпізнавання мови, круговий цикл, таблиці перемикання розкладки, парсинг слів, обробка UTF-16, захист від повторних спрацьовувань) знаходиться у модулі `PuntoCore`.
- **НЕ потрібно** перезапускати GUI-застосунок, щоб протестувати логіку перетворення.
- Запускайте автономний раннер тестів:
  ```bash
  swift build -c release --scratch-path .build && .build/release/PuntoCoreTestsRunner
  ```
- Тести виконуються за 0.5 секунди без вікон, без клацання мишкою і без будь-яких прав Доступності.

### Правило 2. Єдиний канонічний шлях для GUI: `/Applications/FreePunto.app`
- Ніколи не тестуйте ручну взаємодію з `dist/FreePunto.app`.
- Завжди копіюйте збірку в `/Applications/FreePunto.app`.
- Користувач дає дозвіл один раз саме для `/Applications/FreePunto.app`.

### Правило 3. Стабільний номер збірки при локальній розробці
- У `build_app.sh` за замовчуванням `BUILD_NUMBER="1"`.
- Змінюйте номер збірки тільки для релізних тегів.

### Правило 4. Завжди запускати через `open`
- Запуск:
  ```bash
  open /Applications/FreePunto.app
  ```
- Ніколи не запускайте бінарник напряму через фоновий процес термінала для тестування глобальних хоткеїв.

### Правило 5. Акуратний перезапуск процесу
- Перед заміною бандла обов'язково дочекайтеся завершення старого процесу:
  ```bash
  pkill -x FreePunto 2>/dev/null || true
  while pgrep -x FreePunto >/dev/null; do sleep 0.1; done
  rm -rf /Applications/FreePunto.app
  cp -R dist/FreePunto.app /Applications/FreePunto.app
  xattr -dr com.apple.quarantine /Applications/FreePunto.app 2>/dev/null || true
  open /Applications/FreePunto.app
  ```

### Правило 6. Використання `prompt: true` на старті
- У `AppDelegate.swift` перевірка на старті викликається з `prompt: true`. Це гарантує, що якщо дозвіл злетів через зміну `CDHash`, macOS сама покаже системне вікно «FreePunto запитує доступ до керування» та автоматично додасть рядок у Системні параметри.

### Правило 7. Діагностичний лог за замовчуванням у `/tmp/freepunto_debug.log`
- У тестових збірках лог за замовчуванням пишеться у `/tmp/freepunto_debug.log`.
- Переглядати в реальному часі:
  ```bash
  tail -f /tmp/freepunto_debug.log
  ```
