# Сценарії читання і заміни тексту

Документ фіксує, як FreePunto має добиратися до тексту в різних застосунках і в якому порядку пробувати способи. Цілі команди тільки дві:

- виділений текст;
- останнє слово перед курсором.

Окремої цілі "весь рядок" немає. У браузерах рядок може використовуватися тільки як технічний спосіб знайти останнє слово, якщо акуратніший спосіб не спрацював.

FreePunto залишається ручною macOS-утилітою: він працює тільки після команди користувача, не веде історію введення, не робить автокорекцію і не надсилає текст у мережу.

## Загальна модель

Команда проходить одним ланцюжком:

```text
гаряча клавіша або пункт меню
  -> AppDelegate.performTextCommand(...)
  -> TextIOController.readTarget()
  -> PuntoCore будує заміну
  -> TextIOController.replace(...)
  -> InputSourceController перемикає системну розкладку
```

Порядок мов у послідовному режимі фіксований:

```text
EN -> RU -> UA -> EN
```

Якщо потрібної системної розкладки немає в macOS, текст усе одно має перетворитися на наступну цільову мову, а помилка має з'явитися тільки на етапі перемикання системного input source.

## Контекстні сигнали

FreePunto не має вгадувати конкретний сайт за заголовком вікна. Заголовок браузерної вкладки не використовується як джерело рішення для Google Sheets, CanvasTable або інших таблиць.

Дозволені сигнали:

1. `bundleIdentifier` активного застосунку: terminal, browser, code editor, other.
2. `AXRole` активного Accessibility element.
3. `AXEditable` активного Accessibility element.
4. Факт успішного `Cmd+C`: pasteboard був очищений перед спробою і після команди отримав новий непорожній string.

`Cmd+C` доводить тільки те, що текст вдалося прочитати. Він не доводить, що назад можна вставляти прямим `Cmd+V`.

## Два способи читання

FreePunto використовує тільки два способи отримати текст:

1. `Cmd+C` -> `NSPasteboard`.
2. `AXValue`.

`AXSelectedText`, `AXSelectedTextRange`, `Option+Shift+Left`, `Cmd+Shift+Left`, double click, `Return`, `F2` і `Cmd+A` не є способами читання. Їх не можна використовувати для видобування тексту в базовому алгоритмі.

`F2` дозволений тільки як підготовка до запису в browser/grid контексті: увійти в режим редагування активної комірки перед `Cmd+A` і `Cmd+V`.

## Цілі Команди

Є тільки дві цілі:

1. Текст, який користувач явно виділив або який активний grid/canvas зміг віддати через `Cmd+C`.
2. Останнє слово.

FreePunto не змінює слово всередині поля без явного виділення. Якщо користувачу потрібно змінити середину тексту, він має виділити потрібний фрагмент сам.

## Успіх Читання

### `Cmd+C`

Перед кожною copy-спробою:

1. Зберегти snapshot pasteboard.
2. Очистити pasteboard.
3. Запам'ятати `changeCount`.
4. Надіслати `Cmd+C`.
5. Дочекатися нового string у pasteboard.
6. Відновити попередній pasteboard.

Спроба успішна тільки якщо `changeCount` змінився і новий string непорожній.

Для code editor треба відкидати автоматичний line-copy як користувацьке виділення. У VS Code/Cursor/Antigravity такий line-copy може бути лише технічним fallback для отримання останнього слова, коли AX недоступний.

### `AXValue`

Спроба успішна тільки якщо активний Accessibility element віддав непорожній string і з нього можна отримати останнє слово.

Для terminal береться останнє слово з останнього релевантного рядка terminal buffer. Для звичайного editable element береться останнє слово з `AXValue`; якщо користувач хоче змінити слово не в кінці значення, він має виділити його вручну.

## Сценарії

### Terminal.app та інші термінали

Профіль визначається через `bundleIdentifier`.

Читання:

1. Тільки `AXValue`.
2. Беремо останній релевантний рядок terminal buffer.
3. Беремо останнє слово з цього рядка.

Заміна:

1. Standalone terminal: видалити останнє слово terminal-safe способом, потім `Cmd+V`.
2. Integrated terminal: видалити прочитану кількість символів через Backspace, потім `Cmd+V`.

Заборонено:

- `Cmd+C` як основний спосіб читання;
- `Control+C`;
- `Return`;
- `F2`;
- `Cmd+A`;
- double click;
- `Cmd+Shift+Left`.

### Editable text

Це поле або редактор, де `AXEditable == true` або `AXRole` явно вказує на редагований текстовий контекст.

Читання:

1. Спочатку `Cmd+C`.
2. Якщо `Cmd+C` дав текст, це користувацьке виділення.
3. Якщо `Cmd+C` не дав текст, пробуємо `AXValue` і беремо останнє слово.

Заміна:

1. Для тексту, отриманого через `Cmd+C`, вставити replacement через `Cmd+V` поверх поточного виділення.
2. Для останнього слова з `AXValue`, видалити довжину слова і вставити replacement через `Cmd+V`.

### Code editor

Профіль визначається через `bundleIdentifier` для VS Code, Cursor, Antigravity та споріднених редакторів.

Читання:

1. Спочатку `Cmd+C`.
2. Якщо copy схожий на автоматичний line-copy без виділення, результат не приймається як виділений текст.
3. Для VS Code/Cursor/Antigravity можна витягнути останнє слово з line-copy fallback, якщо це єдиний доступний робочий шлях.
4. Якщо `Cmd+C` не дав реального виділення або line-copy fallback не дав слова, пробуємо `AXValue` і беремо останнє слово.

Заміна:

1. Для реального виділення: `Cmd+V`.
2. Для останнього слова: видалити прочитану довжину і вставити replacement через `Cmd+V`.

Відомий баг, який не можна повертати: редактор копіює рядок без виділення, а FreePunto приймає його як користувацький target.

### Browser editable

Це браузер, але активний element редагований: textarea, input, search field, contenteditable або інший element з `AXEditable == true`.

Читання:

1. Спочатку `Cmd+C`.
2. Якщо `Cmd+C` дав текст, це виділення.
3. Якщо `Cmd+C` не дав текст, пробуємо `AXValue` і беремо останнє слово.

Заміна:

1. Для виділення: `Cmd+V`.
2. Для останнього слова: видалити довжину слова і вставити replacement через `Cmd+V`.

### Browser non-editable / grid-like

Це браузер, але активний element не виглядає редагованим. Так працюють Google Sheets, CanvasTable та інші canvas/grid інтерфейси.

Читання:

1. Тільки `Cmd+C`.
2. Якщо `Cmd+C` дав текст, вважаємо його grid-like target.
3. Якщо `Cmd+C` не дав текст, команда завершується помилкою або beep.

Заміна:

1. Не вставляти прямим `Cmd+V` у grid/canvas.
2. Натиснути `F2`, щоб увійти в режим редагування активної комірки.
3. Після `F2` перевірити, що активний контекст став редагованим.
4. Натиснути `Cmd+A` всередині edit mode.
5. Натиснути `Cmd+V`.
6. Натиснути `Cmd+A` ще раз, щоб увесь результат залишився виділеним для повторного перетворення.
7. Не натискати `Return` після вставки.

Якщо `F2` не ввів активну комірку в edit mode, FreePunto не має робити прямий paste у grid. Потрібно показати помилку або beep.

`Escape` не використовується як cleanup після читання: якщо користувач уже був у режимі редагування, `Escape` може викинути його з комірки.

### Other

Для інших застосунків використовується той самий безпечний порядок:

1. Якщо контекст editable: `Cmd+C`, потім `AXValue`.
2. Якщо контекст non-editable: тільки `Cmd+C`; якщо він дав текст, але немає безпечного способу запису, не вставляти назад.

## Зведена таблиця

| Сценарій | Читання | Заміна |
| --- | --- | --- |
| Terminal | `AXValue` -> останнє слово | terminal-safe delete word -> `Cmd+V` |
| Editable text | `Cmd+C`, інакше `AXValue` -> останнє слово | `Cmd+V` або delete word -> `Cmd+V` |
| Code editor | `Cmd+C` без line-copy для виділення; line-copy fallback або `AXValue` -> останнє слово | `Cmd+V` або delete word -> `Cmd+V` |
| Browser editable | `Cmd+C`, інакше `AXValue` -> останнє слово | `Cmd+V` або delete word -> `Cmd+V` |
| Browser non-editable / grid-like | `Cmd+C` | `F2` -> verify edit mode -> `Cmd+A` -> `Cmd+V` -> `Cmd+A` |

## Що вважати багом

- У документі або коді з'являється окрема ціль "весь рядок".
- Для читання додаються способи поза `Cmd+C` і `AXValue`.
- Рішення про Google Sheets або CanvasTable приймається за `windowTitle`.
- Terminal отримує `Control+C`, `Return`, `F2`, `Cmd+A`, double click або `Cmd+Shift+Left`.
- Code editor приймає автоматичний line-copy як виділений текст.
- Browser/grid вставляє заміну прямим `Cmd+V` без входу в edit mode через `F2`.
- Browser/grid використовує `Return` або double click для входу в edit mode.
- `Escape` виконується після читання і викидає користувача з edit mode.
- Browser/grid натискає `Return` після вставки.
- Browser/grid не залишає результат виділеним після вставки.
- Pasteboard не відновлюється після читання або вставки.

## Що перевіряти вручну після змін

- Terminal без виділення: замінюється останнє слово.
- Terminal не отримує `Control+C`, `Return`, `F2`, `Cmd+A`, double click або `Cmd+Shift+Left`.
- Виділений текст у VS Code замінюється як виділення.
- VS Code без виділення не приймає автоматично скопійований рядок як target.
- Останнє слово у VS Code замінюється через `AXValue`-сценарій.
- Cursor і Antigravity проходять ті самі перевірки, що й VS Code: editor selection, editor last-word fallback, integrated terminal.
- Виділений текст у Chrome textarea/contenteditable замінюється через `Cmd+C` -> `Cmd+V`.
- Останнє слово у Chrome textarea/contenteditable замінюється через `AXValue`.
- Browser non-editable/grid читається через `Cmd+C`, входить у edit mode через `F2`, вставляє через `Cmd+A` -> `Cmd+V`, не використовує прямий paste у grid.
- CanvasTable підтримує `F2` як вхід у редагування активної комірки.
- Google Sheets з активною ячейкою підтримує `F2`-сценарій.
- Повторне перетворення після browser/grid paste працює, бо результат залишається виділеним.
- Повторне перетворення йде `EN -> RU -> UA -> EN`.
