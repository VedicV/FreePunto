# Сценарії читання і заміни тексту

Документ фіксує, як FreePunto має добиратися до тексту в різних застосунках і в якому порядку пробувати способи. Цілі команди тільки дві:

- виділений текст;
- останнє слово перед курсором.

Окремої цілі "весь рядок" немає. У браузерах рядок може використовуватися тільки як технічний спосіб знайти останнє слово, якщо акуратніший спосіб не спрацював.

FreePunto залишається ручною macOS-утилітою: він працює тільки після команди користувача, не веде історію введення, не робить автокорекцію і не надсилає текст у мережу.

## Загальна модель

Команда проходить одним ланцюжком:

```text
гаряча клавіша або пункт меню
  -> AppDelegate.performTextCommand(...)
  -> TextIOController.readTarget()
  -> PuntoCore будує заміну
  -> TextIOController.replace(...)
  -> InputSourceController перемикає системну розкладку
```

Порядок мов у послідовному режимі фіксований:

```text
EN -> RU -> UA -> EN
```

Якщо потрібної системної розкладки немає в macOS, текст усе одно має перетворитися на наступну цільову мову, а помилка має з'явитися тільки на етапі перемикання системного input source.

## Базові способи добратися до тексту

### Виділений текст

Пріоритети:

1. Accessibility: `AXSelectedText`, якщо застосунок нормально віддає виділення.
2. Pasteboard: тимчасовий `Cmd+C` зі snapshot/restore старого вмісту.
3. Для застосунків, де `Cmd+C` без виділення копіює рядок або комірку, pasteboard приймається тільки після підтвердження реального виділення через Accessibility.

### Останнє слово

Пріоритети:

1. Accessibility без візуального ефекту: `AXValue` + `AXSelectedTextRange`, обчислити слово ліворуч від курсора.
2. Word navigation: `Option+Shift+Left`, потім `Cmd+C`.
3. Line selection fallback: `Cmd+Shift+Left`, потім `Cmd+C`, обчислити останнє слово в лівій частині рядка, повернути курсор і виділити тільки слово.

Line selection fallback допустимий тільки там, де він не ламає активний застосунок. У браузерах це запасний варіант, бо візуальне виділення виглядає погано; у терміналі line selection не використовується.

## Заміна тексту

Базові способи:

1. Accessibility replacement: виставити `AXSelectedTextRange`, потім записати `AXSelectedText`.
2. Pasteboard replacement: покласти заміну в pasteboard, виконати `Cmd+V`, потім відновити попередній pasteboard.
3. Для web/editor профілів перед вставкою допускається `Delete`, щоб прибрати нестабільне selection.

Окремого власного undo немає. Очікуємо native undo stack цільового застосунку, наскільки це дозволяє сам застосунок.

## Сценарії

### Terminal.app та інші термінали

Профіль: `terminal`.

Виділений текст:

1. Не використовуємо як основний сценарій.
2. Не розраховуємо, що користувач зможе виділити редагований текст у терміналі.

Останнє слово:

1. Основний сценарій для термінала.
2. Читання: спочатку `AXValue` активного terminal element і останнє слово в поточному рядку.
3. Якщо AX не дав текст - fallback `Option+Shift+Left` + `Cmd+C`.
4. Заміна: `Control+W` видаляє попереднє слово, потім `Cmd+V` вставляє результат.
5. `Cmd+Shift+Left` не використовується.

Практичне правило: у терміналі FreePunto працює з останнім словом перед курсором, а не з довільним виділенням.

### Chrome

Профіль: `browser`, окрім Google Sheets.

Виділений текст:

1. `Cmd+C` через pasteboard.
2. Якщо pasteboard порожній або не спрацював - `AXSelectedText`.

Останнє слово:

1. Спочатку пробуємо Accessibility без візуального виділення: `AXValue` + `AXSelectedTextRange`.
2. Якщо не вийшло - поточний keyboard fallback через line selection.
3. Word navigation fallback вимкнений.

Заміна:

1. Pasteboard + `Delete` + `Cmd+V`.
2. Accessibility replacement як запасний шлях.

### Firefox

Профіль: `browser`.

Виділений текст:

1. `Cmd+C` через pasteboard.
2. `AXSelectedText` як запасний шлях.

Останнє слово:

1. Спочатку Accessibility без візуального виділення.
2. Якщо не вийшло - line selection fallback.
3. Для Firefox допускаються ролі `AXGroup`, `AXWindow`, `AXApplication`, бо дерево Accessibility може бути менш точним, ніж у Chrome.

Заміна:

1. Pasteboard + `Delete` + `Cmd+V`.
2. Accessibility replacement як запасний шлях.

### VS Code

Профіль: `vscode`.

Виділений текст:

1. Спочатку пробуємо pasteboard через `Cmd+C`.
2. Pasteboard приймається тільки якщо Accessibility підтверджує, що є реальне виділення: `AXSelectedText` або ненульовий `AXSelectedTextRange`.
3. Якщо Monaco не віддав AX-підтвердження, pasteboard можна прийняти без AX тільки коли текст не схожий на автоматичний line-copy VS Code без виділення.
4. Перевірка `AXEditable` не має блокувати читання виділення: Monaco може не виглядати як звичайне macOS text field.
5. Якщо виділення було, не можна падати в сценарій останнього слова.

Причина: у VS Code `Cmd+C` без виділення копіює весь поточний рядок. Це не можна вважати користувацьким виділенням.

Останнє слово:

1. Accessibility: `AXValue` + `AXSelectedTextRange`.
2. Word navigation: `Option+Shift+Left`, потім `Cmd+C`.
3. Line selection fallback.

Заміна:

1. Pasteboard + `Delete` + `Cmd+V`.
2. Accessibility replacement як запасний шлях.

Відомий баг, який не можна повертати: VS Code вибирає і замінює останнє слово, хоча користувач виділив інший текст.

### Google Sheets

Профіль: `googleSheets`, визначається як браузерний застосунок із заголовком вікна Google Sheets.

#### Canvas/grid режим

Це режим, коли активна комірка на canvas, але користувач ще не редагує текст усередині комірки.

Читання:

1. Тільки `Cmd+C` через pasteboard.
2. Отриманий текст вважається повним текстом активної комірки.
3. Не намагаємося читати останнє слово.
4. Не намагаємося використовувати browser line selection.

Заміна:

1. `Escape` скидає copy-mode після читання активної комірки через `Cmd+C`.
2. `Return` відкриває редагування активної комірки.
3. `Cmd+A` виділяє весь текст усередині редагованої комірки.
4. `Cmd+V` вставляє весь перетворений текст.
5. Ще раз `Cmd+A`, щоб увесь результат залишився виділеним.
6. `Return` після вставки не натискаємо.

Після цього користувач сам вирішує, що робити: прийняти зміну, скасувати, відредагувати вручну або ще раз натиснути FreePunto, щоб замінити мову всього тексту.

Відомий баг, який не можна повертати: якщо вставляти результат прямо в grid/canvas без входу в режим редагування, Google Sheets може скопіювати комірку і вставити результат у дві комірки.

#### Режим редагування комірки

Якщо користувач уже редагує текст усередині комірки, поведінка така сама, як у браузері:

1. Якщо є виділений текст - працюємо з виділенням.
2. Якщо виділення немає - працюємо з останнім словом.
3. Увесь текст комірки не замінюється автоматично.

### Звичайний текстовий редактор, Telegram, Notes, Messages і схожі застосунки

Профіль: `standard`.

Виділений текст:

1. `AXSelectedText`.
2. Pasteboard через `Cmd+C`.

Останнє слово:

1. Accessibility: `AXValue` + `AXSelectedTextRange`.
2. Line selection fallback.
3. Word navigation fallback за замовчуванням не використовується.

Заміна:

1. Accessibility replacement.
2. Pasteboard + `Cmd+V`.

## Зведена таблиця

| Сценарій | Виділений текст | Останнє слово | Заміна |
| --- | --- | --- | --- |
| Terminal | ні | AX current line -> word navigation copy | `Control+W` + pasteboard |
| Chrome | pasteboard -> AX | AX без візуального ефекту -> line selection fallback | pasteboard + `Delete` -> AX |
| Firefox | pasteboard -> AX | AX без візуального ефекту -> line selection fallback | pasteboard + `Delete` -> AX |
| VS Code | pasteboard з AX-підтвердженням -> AX | AX -> word navigation -> line selection | pasteboard + `Delete` -> AX |
| Google Sheets canvas | повний текст комірки через `Cmd+C` | ні | `Escape` -> `Return` edit -> `Cmd+A` -> paste -> `Cmd+A` |
| Google Sheets edit mode | як браузер | як браузер | як браузер |
| TextEdit/Telegram/etc. | AX -> pasteboard | AX -> line selection | AX -> pasteboard |

## Що вважати багом

- У документі або коді з'являється окрема ціль "весь рядок".
- Terminal намагається працювати з довільним виділенням замість останнього слова.
- Terminal використовує `Cmd+Shift+Left`.
- Browser одразу робить візуальне line selection, хоча можна прочитати останнє слово через Accessibility.
- VS Code падає в останнє слово за наявності виділеного тексту.
- VS Code приймає рядок, скопійований `Cmd+C` без виділення, як користувацьке виділення.
- Google Sheets canvas вставляє заміну прямо в grid/canvas, а не входить у редагування комірки.
- Google Sheets canvas натискає `Return` після вставки.
- Google Sheets canvas не залишає весь результат виділеним після вставки.
- Pasteboard не відновлюється після читання або вставки.

## Що перевіряти вручну після змін

- Terminal без виділення: замінюється останнє слово.
- Terminal не надсилає `Cmd+Shift+Left`.
- Виділений текст у VS Code замінюється як виділення.
- VS Code без виділення не приймає звичайний скопійований рядок як виділення.
- Останнє слово у VS Code.
- Виділений текст у Chrome textarea/contenteditable.
- Останнє слово у Chrome textarea/contenteditable спочатку пробує невізуальний AX шлях.
- Те саме у Firefox.
- Google Sheets на canvas: копіюється активна комірка, copy-mode скидається, edit mode відкривається клавіатурою, вставка без фінального `Return`, результат залишається виділеним.
- Google Sheets в edit mode: поведінка як у браузері.
- Виділений текст і останнє слово в TextEdit/Notes/Telegram.
- Повторне перетворення йде `EN -> RU -> UA -> EN`.
