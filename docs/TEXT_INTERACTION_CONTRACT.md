# Чинний контракт взаємодії з текстом

Оновлено: 2026-09-07. Цей документ визначає поведінку поточного коду. Старі плани `TEXT_INTERACTION_SCENARIOS.md`, `TEXT_TARGET_RETRIEVAL_POLICY.md` та `TEXT_INTERACTION_IMPLEMENTATION_PLAN.md` описують попередню модель і не повинні слугувати підставою для відновлення видалених fallback-механізмів.

## Мета та область підтримки

FreePunto читає текст за явною командою. Область — підтверджене виділення або слово безпосередньо ліворуч від курсора. Для AX-діапазону слово обмежується пробільними символами; точний хвіст пробілів/tab/NBSP зберігається. На порожньому рядку слово з попереднього рядка не вибирається. Максимальна довжина слова — 300 UTF-16 одиниць. Діапазон не може розривати emoji або складений символ.

Послідовний цикл EN → RU → UA → EN пропускає кроки, які не змінюють текст: `csh → сыр → сір → csh`, але `ghbdtn → привет → ghbdtn`. Цикл прив'язаний до конкретного поля та підтвердженого тексту, він не переноситься між однаковими словами в різних полях.

## Операція

1. Захопити актуальні PID, вікно та AX-елемент. Команда, скасована введенням/кліком/зміною налаштувань до початку фонової роботи, не відновлюється.
2. Прочитати знімок тексту та діапазону. Для вже підтвердженого термінального елемента спочатку перевірити явне виділення через `Cmd+C`; без виділення дозволити лише останнє слово валідного промпту з поточного `AXValue`.
3. Підготувати перетворення та отримати token. Скидання (reset), нова підготовка або інша команда інвалідують попередній token.
4. Повторно перевірити ціль, вихідне значення та виділення. Вибрати одну стратегію запису. За необхідності підготувати точне виділення та перевірити його вміст.
5. Надіслати один запис. Помилка AX після спроби запису може свідчити про часткову зміну; переходити до paste/Backspace після неї суворо заборонено.
6. Підтвердити результат через повне очікуване значення або допустиме точне виділення. Для Monaco/VS Code, Chromium-вебвмісту та термінала діє вузький виняток: якщо `Cmd+V` успішно надіслано і PID, вікно та фокусний AX-елемент не змінилися, операція вважається підтвердженою без повного `AXValue`. Це потрібно, бо прихований Monaco textarea і деякі вебкомпоненти повертають лише локальний зріз або `nil`.
7. Лише підтверджений запис в актуальну ціль дозволяє commit та перемикання системної розкладки. За невідомого результату розкладка не змінюється, користувач отримує звуковий сигнал і пояснення у tooltip значка.

Поки команда виконується, нові текстові команди не ставляться в чергу за старим фокусом; стан «зайнято» повідомляється через tooltip і звук. Звичайне введення та кліки скасовують решту дій. Системні глобальні події не є атомарною транзакцією зі стороннім застосунком: перевірки зменшують вікно перегонів (race condition), але не дають абсолютної гарантії відсутності зовнішніх змін.

## Результати та повтор

Публічні імена enum збережено для зворотної сумісності:

| Результат | Значення | Наступна дія |
| --- | --- | --- |
| `successVerified` | Перевірено результат запису в ту саму ціль | Commit token та зміна розкладки |
| `failed` | Запис не розпочинався; підготовка могла змінити виділення або режим редагування | Відновити вихідне виділення тільки за збереження колишнього фокусу; не продовжувати запис |
| `deliveredUnconfirmedAX` | Запис було здійснено, результат може бути частковим або відсутнім | Не записувати повторно і не змінювати розкладку; зберегти receipt для звірки |

За невідомого результату повторне читання того самого початкового тексту блокується. Свіжий очікуваний результат дозволяє продовжити цикл. Зміна поля, тексту або явна дія користувача скидає попередній контекст. Зникнення AX не розцінюється ані як підтвердження успіху, ані як провал.

## Адаптери

| Поверхня | Поточна поведінка |
| --- | --- |
| Нативне editable поле | Читання перевіреного AX selection/range, один AX-запис або paste за точним виділенням |
| IDE editor/search/chat | Вимагається позитивна ідентифікація поверхні редагування. Якщо Monaco читає слово, але не дозволяє встановити `AXSelectedTextRange`, використовується `Option+Shift+Left` → `Cmd+C` → `Cmd+V`; незмінний фокус підтверджує доставлену вставку |
| Chrome та Chromium | На будь-якій вебсторінці спочатку читається явне виділення через `Cmd+C`, навіть для `AXGroup` або static text. Для фокусного `contenteditable`/textarea/input дозволено клавіатурне виділення слова, коли обидва AX-атрибути виділення дорівнюють `nil` |
| Firefox release/developer/nightly | `Cmd+C` та збережене виділення; `AXSelectedTextRange` не використовується. Без виділення клавіатурний fallback дозволений для editable поля навіть тоді, коли обидва AX-атрибути виділення дорівнюють `nil` |
| Клавіатурний fallback | `Option+Shift+Left` виділяє одиницю за правилами macOS; перетворюється саме скопійоване виділення. Межі пунктуації можуть відрізнятися від AX scanner |
| Browser grid | F2 дозволено для розпізнаної комірки; editor повинен належати їй і містити точний вихідний текст. Інакше — відмова до paste. Це може обмежити підтримку окремих web-grid |
| Термінал через GUI AX | Явне виділення замінюється через `Cmd+C`/`Cmd+V`. Без виділення останнє слово береться лише з валідного промпту; перед зміною знімок перевіряється повторно, далі надсилається точна кількість `Backspace` за `String.count` і один `Cmd+V`. Порожній або невалідний буфер дає безпечну відмову |
| Локальний zsh | Додатковий widget та `punto-transform` працюють з LBUFFER/RBUFFER. Налаштування описано в [TERMINAL_INTEGRATION.md](TERMINAL_INTEGRATION.md) |

Zsh widget — додатковий точніший шлях для локального zsh, який працює без парсингу AX-відображення. Він не підключений до глобального одиночного Control і не синхронізує налаштування/системну розкладку GUI. GUI-шлях тепер знову доступний у standalone та integrated terminal, але потребує живої перевірки конкретного термінала й промпту.

## Буфер обміну (Clipboard) та діагностика

Snapshot pasteboard відновлюється лише у разі збігу `changeCount` з версією, якою володіє операція. Зовнішня копія зберігається. Відповідь Cmd+C не містить transaction ID: її версія приймається у володіння лише за незалежного збігу AX selected text. Якщо такого доказу немає, скопійований текст може залишитися в clipboard, щоб не затерти можливу зовнішню копію. Гарантії відновлення старого clipboard у такому випадку немає.

Paste використовує обмежене очікування 450 мс. Звичайні AX-поля після цього перевіряються за значенням або виділенням. Для Monaco/VS Code, Chromium-вебвмісту та підтвердженого термінала застосовується описана вище перевірка незмінного фокусного елемента.

Текст користувача, вміст clipboard та значення AX identity не записуються у штатний trace. Debug-збірки пишуть метадані у `/tmp/freepunto_debug.log`; release пише файл лише за явної наявності `FREEPUNTO_LOG_FILE`. Старі логи попередніх версій автоматично не видаляються.

## Перевірки та незавершена робота

Перевірено в загальній збірці 2026-09-07:

- `swift build -c release --scratch-path .build` — успішно.
- `PuntoCoreTestsRunner` — 215 перевірок пройдено, включно зі стратегіями terminal/Chromium, правилом Monaco paste, engine tokens/receipts, production replacement executor, UTF-16 та clipboard ownership. Перевірки конкретних системних розкладок запускаються окремо через `PUNTO_TEST_SYSTEM_LAYOUTS=1`.
- `python3 integrations/zsh/test_integration.py .build/release/punto-transform` — subprocess/PTY-перевірки загальної збірки пройшли успішно без запуску набраних shell-команд.
- Додатковий тимчасовий harness для XCTest цього разу не запускався; канонічною автономною перевіркою лишається `PuntoCoreTestsRunner`.
- `swift test` у локальних Command Line Tools зупинився на `no such module 'XCTest'`. Справжнє виконання XCTest вимагає повного Xcode.

Лог запущеної до цих змін тестової версії підтвердив Antigravity `com.google.antigravity-ide`, `AXTextArea`, `Message input`: `Cmd+V` надсилався, але стара загальна перевірка відкидала результат через локальний `AXValue` Monaco. Живі вікна Terminal/Chrome/VS Code/Antigravity з новим бінарником ще не перевірялися. Встановлений `.app`, shell-конфігурація користувача та TCC у цій роботі не змінювалися. Перед випуском потрібна матриця ручного тестування з [MANUAL_TEXT_INTERACTION_QA.md](MANUAL_TEXT_INTERACTION_QA.md), з окремими статусами PASS/FAIL/UNSUPPORTED/NOT TESTED.

Наступні самостійні етапи: ручне UI QA нового бінарника в Terminal.app, VS Code/Antigravity terminal і chat, Chrome textarea/contenteditable/static selection та Firefox; потім, за потреби, окремий Firefox WebExtension і перевірка конкретних grid. Зміни installer/signing з аудиту не входять до цієї стабілізації текстового I/O.
