# Локальна інтеграція FreePunto з zsh

FreePunto має два термінальні шляхи. 

### 1. Основний GUI-шлях (глобальна гаряча клавіша)

- **Заміна виділеного мишкою тексту**: У термінальних емуляторах (VS Code, Antigravity, Terminal.app) виділення мишкою є суто візуальним шаром для буфера копіювання — сам шел (zsh/bash) не знає про виділений фрагмент. З версії **v0.3.0** FreePunto при виявленні виділеного однорядкового тексту (до 120 символів) автоматично надсилає відповідну кількість `Backspace` перед виконанням `Cmd+V`. Це витирає вихідне слово з промпту і вставляє перетворений текст, усуваючи проблему дописування слова в кінець.
- **Особливість `Shift + Стрілки` у терміналі (поява символів `2D`)**: На відміну від звичайних графічних текстових полів, емулятор термінала транслює `Shift + Left Arrow` як ANSI/xterm ескейп-код `\e[1;2D`. Оскільки в стандартному zsh/bash немає прив'язки для виділення тексту стрілками, оболонка ігнорує префікс керування і друкує символи `2D` в командний рядок. Для виділення тексту в терміналі використовуйте мишку або нативні комбінації оболонки.
- **Автоматичне перетворення слова перед курсором (без мишки)**:
  - У **macOS Terminal.app** атрибут `AXValue` доступний за замовчуванням: FreePunto автоматично перетворює останнє слово валідного промпту через Backspace + Paste.
  - В **інтегрованих терміналах VS Code / Antigravity** (`xterm.js` малює символи на `<canvas>`, тому `AXValue` типово порожній). Щоб увімкнути читання промпту без мишки, активуйте режим доступності термінала комбінацією **`Option + F2`** (або через налаштування: `"terminal.integrated.screenReaderMode": "on"`).

### 2. Нативний ZLE-віджет для zsh (без буфера обміну та симуляції клавіш)

## Увімкнення в поточній shell-сесії

Потрібні zsh, Python 3 та зібраний Swift helper. Із кореня репозиторію:

```sh
swift build -c release --product punto-transform
source integrations/zsh/freepunto.zsh
bindkey '^X^P' freepunto-layout
```

Натисніть Ctrl+X, потім Ctrl+P під час редагування команди. Віджет нічого не виконує і не натискає Enter. Ця комбінація може перевизначити наявну прив'язку поточної keymap; перевірте її через `bindkey '^X^P'` перед призначенням. Файл сам реєструє widget, але не змінює key bindings, `.zshrc`, системні дозволи чи налаштування IDE. Для іншого розташування helper задайте абсолютний шлях `FREEPUNTO_HELPER` перед `source`; Python можна вибрати через `FREEPUNTO_PYTHON`.

```sh
FREEPUNTO_HELPER=/absolute/path/punto-transform
FREEPUNTO_PYTHON=python3
source /absolute/path/Punto/integrations/zsh/freepunto.zsh
```

Для видалення тестової прив'язки використайте `bindkey -r '^X^P'` (або відновіть раніше збережену прив'язку). Після закриття shell-сесії зміни зникають.

## Контракт та обмеження

- Віджет запускається тільки за явною командою ZLE. Текст передається через stdin, а не через команду shell, `eval`, argv чи history. Команди з буфера не виконуються.
- `bridge.py` кодує JSON і викликає helper як subprocess із таймаутом 3 секунди. Відповідь перевіряється до зміни `LBUFFER`; у разі помилки буфер залишається незмінним. Текст не виводиться в повідомленнях про помилки і не зберігається на диск.
- Helper приймає один JSON-запит версії 1 розміром до 1 MiB і повертає JSON. `leftBuffer` завершується строго біля курсора; `rightBuffer` повертається без змін. NUL-байти заборонені протоколом.
- `session` зберігається лише в змінній поточної оболонки після підтвердження присвоєного буфера. Він прив'язаний до точних лівого та правого буферів. Будь-який інший ZLE widget, включно з введенням, рухом курсора та виконанням рядка, скидає продовження циклу під час наступного виклику FreePunto.
- Між окремими викликами helper цикл відновлюється обмеженим повтором початкового перетворення (до трьох кроків) у свіжому екземплярі `PuntoEngine`. Зміна тексту/позиції або неузгоджений session починає новий цикл.
- «Слово» — непробільний фрагмент до курсора, до 300 UTF-16 одиниць. Це не парсер shell: пунктуація, лапки та оператори всередині вибраного фрагмента також можуть перетворитися за картою розкладки. Користувач перевіряє команду перед її звичайним виконанням.
- У середині слова перетворюється лише частина ліворуч від курсора. Виділення ZLE `REGION_ACTIVE` не використовується. Штатна робота застосунку через AX та цей віджет — це різні шляхи.

Приклад запиту (поле `session` із попередньої відповіді передається без змін при повторі):

```json
{"version":1,"leftBuffer":"echo ghbdtn \t","rightBuffer":" tail","session":null}
```

Перша відповідь містить `leftBuffer: "echo привет \t"`, незмінний `rightBuffer` та об'єкт `session` для наступного виклику.

## Перевірка

`PuntoCoreTestsRunner` перевіряє, що текст, схожий на prompt, не визначає термінальний маршрут, локальна AX-ідентичність батьківських елементів враховується, межі editor/window зупиняють пошук, родина Firefox використовує єдину політику діапазонів, а сканер зберігає точні пробільні символи та межу поточного рядка.

`python3 integrations/zsh/test_integration.py /absolute/path/punto-transform` перевіряє реальний helper, bridge та widget в окремому zsh PTY без зміни конфігурації користувача. Результати цього тесту стосуються локального zsh, а не живої перевірки UI VS Code/Antigravity.

Перевірено локально 2026-09-06: macOS 15.7.9 arm64, zsh 5.9, Python 3.11.4, Swift 6.2.4. Ізольована збірка всіх джерел `PuntoCore` та helper через `swiftc` пройшла успішно; 21 assertion з `TerminalChecks.swift` пройдено. `test_integration.py` пройшов увесь набір тестів subprocess/PTY, включно з 1/2/3/6 послідовними викликами, відновленням після іншої команди ZLE, точними tabs/NBSP/emoji, багаторядковим буфером, коректною відмовою за відсутності helper та відсутністю виконання shell substitution із буфера. Живі вікна VS Code, Antigravity та Firefox у цій перевірці не використовувалися.
